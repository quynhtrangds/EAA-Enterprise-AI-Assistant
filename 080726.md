Mỗi schema được gán vào thuộc tính `outputSchema` tương ứng của từng MCP tool, để `McpRuntime.validateOutput(...)` có thể validate kết quả trả về sau khi tool execute.

### 2. Chuẩn hóa output theo camelCase đúng spec PDF

Đã chuẩn hóa output của các tool để không còn trả trực tiếp snake_case từ PostgreSQL.

#### `search_customer`

Trước đây trả `result.rows` trực tiếp, ví dụ:

```json
{
  "id": "uuid",
  "customer_code": "CUS-001",
  "full_name": "Nguyễn Văn A"
}
```

Hiện đã map sang:

```json
{
  "customers": [
    {
      "customerId": "uuid",
      "customerCode": "CUS-001",
      "fullName": "Nguyễn Văn A",
      "phone": "090...",
      "email": "...",
      "status": "active"
    }
  ]
}
```

#### `get_customer_orders`

Đã map output sang:

```json
{
  "orders": [
    {
      "orderId": "uuid",
      "orderCode": "ORD-001",
      "orderDate": "datetime",
      "status": "paid",
      "totalAmount": 26800000
    }
  ]
}
```

#### `get_order_detail`

Đã điều chỉnh để `items` và `payments` được nest bên trong object `order`, đúng cấu trúc trong PDF spec.

### 3. Các test case đã tự động hóa

#### Test 1 - `GET /health`

Mục tiêu:

- Đảm bảo endpoint health check hoạt động.
- Kỳ vọng HTTP status `200`.
- Kỳ vọng response JSON hợp lệ.

Kỳ vọng response:

```json
{
  "status": "ok",
  "service": "mcp-gateway"
}
```

#### Test 2 - `POST /api/tools/call` với input invalid

Mục tiêu:

- Gọi tool `search_customer` với `limit: 999`.
- Vì `search_customer` chỉ cho `limit` tối đa 20, hệ thống phải chặn trước khi query quá nhiều dòng.

Request chính:

```json
{
  "toolName": "search_customer",
  "arguments": {
    "keyword": "Nguyen",
    "limit": 999
  },
  "sessionId": "test-invalid-limit-..."
}
```

Header:

```http
x-user: manager
```

Kỳ vọng:

- HTTP status `400`
- `errorCode = INVALID_TOOL_INPUT`

#### Test 3 - Permission denied và audit log

Mục tiêu:

- Dùng user `viewer` gọi tool bị cấm `search_customer`.
- Kỳ vọng Gateway trả lỗi permission.
- Xác nhận lỗi vẫn được ghi vào bảng `audit_logs`.

Request chính:

```json
{
  "toolName": "search_customer",
  "arguments": {
    "keyword": "Nguyen",
    "limit": 5
  },
  "sessionId": "test-permission-denied-..."
}
```

Header:

```http
x-user: viewer
```

Kỳ vọng response:

- HTTP status `403`
- `errorCode = PERMISSION_DENIED`

Kỳ vọng audit log:

```text
session_id = sessionId của test
tool_name = search_customer
status = failed
error_message = Ban khong co quyen goi tool nay.
```

### 5. Tác động đến checklist MVP

Điểm trước đó còn thiếu:

- Có test case cơ bản: Chưa đạt

Trạng thái sau cập nhật:

- Có test case cơ bản: Đạt bước đầu

Các test hiện đã bao phủ 3 rủi ro quan trọng:

- Health check service
- Validate input limit vượt mức cho phép
- Permission denied kèm audit log failed

Các test nên bổ sung tiếp:

- Test `get_revenue_summary` happy path.
- Test `search_customer` happy path trả tối đa đúng limit.
- Test `get_order_detail` output schema có nested `items/payments`.
- Test `GET /api/tools` lọc đúng tool theo role.
- Test admin xem được `GET /api/audit-logs`, non-admin bị chặn.
