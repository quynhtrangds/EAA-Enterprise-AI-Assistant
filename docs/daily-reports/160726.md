## 1. Trọng tâm công việc
Trong ngày hôm nay, chúng ta đã tập trung vào việc gỡ lỗi (debug) các vấn đề phát sinh trong quá trình tích hợp LLM với Tool Chaining, khắc phục dữ liệu ảo (seed data) trong Database, và hoàn thiện các task cuối cùng của **Phase 2** (bao gồm Rate Limit và Data Masking).

## 2. Chi tiết các công việc đã thực hiện

### 2.1. Khắc phục lỗi Tool Chaining của LLM (Llama 3 / Groq)
- **Vấn đề**: LLM liên tục gặp lỗi `tool_use_failed` do gọi sai định dạng mảng (Parallel Tool Calling) hoặc gọi những tool không tồn tại.
- **Giải pháp**: 
  - Bổ sung **Luật 13 và 14** vào System Prompt tại `apps/ai-orchestrator/src/services/chat-service.ts`.
  - Ép buộc LLM chỉ được phép gọi **duy nhất 1 tool** trong mỗi lượt phản hồi (Sequential Execution) và phải đợi kết quả trước khi gọi tool tiếp theo.
  - Xử lý mượt mà lỗi hiển thị trên Web UI thông qua cơ chế Graceful Error Handling, chặn lỗi in ra màn hình người dùng.

### 2.2. Khắc phục lỗi trùng lặp dữ liệu Database
- **Vấn đề**: Khi query, các mặt hàng trong đơn hàng bị lặp lại nhiều lần với cùng một dữ liệu.
- **Giải pháp**:
  - Phát hiện lỗi do logic toán học chia lấy dư (`modulo`) trong vòng lặp `generate_series` tại `database/seed/seed.sql`.
  - Cập nhật lại công thức sinh dữ liệu mẫu để phân bổ các mặt hàng (order_items) ngẫu nhiên và không bị trùng lặp vào các đơn hàng (orders).
  - Reset (xoá volume và tạo lại) Database PostgreSQL để nạp dữ liệu chuẩn.

### 2.3. Quản lý Môi trường (Environment Variables)
- Hướng dẫn quy trình cập nhật `OPENAI_API_KEY` trong file `.env` và cách khởi động lại Docker Compose (`docker-compose down && docker-compose up -d`) để hệ thống nhận cấu hình mới thay vì chỉ dùng lệnh restart.

### 2.4. Hoàn thành toàn bộ các Task của Phase 2

**Task 1: Chuẩn hóa MCP Streamable HTTP endpoint**
- Cài đặt thư viện `@modelcontextprotocol/sdk` cho cả Gateway và Orchestrator.
- Triển khai thành công giao thức SSE (Server-Sent Events) tại `mcp-gateway`.
- Tích hợp thành công Client MCP SDK vào `ai-orchestrator` để kết nối thông qua SSE.

**Task 2: Tách PostgreSQL Connector thành MCP Server độc lập**
- Tách riêng biệt package mới tại `packages/mcp-server-postgres`.
- Di chuyển toàn bộ logic kết nối DB từ Gateway sang package độc lập này.

**Task 3: Cơ chế Connector Manifest & Tool Aggregation**
- Khởi tạo file cấu hình `connector.json` quản lý danh sách các MCP Servers kết nối.
- Xây dựng cơ chế cho phép Gateway tự động tổng hợp (aggregate) các công cụ từ nhiều Server khác nhau (bao gồm cả việc giả lập thêm `mcp-server-crm`).

**Task 4: Bảo vệ dữ liệu cá nhân (Data Masking)**
- Viết mới module `MaskingService` tại `mcp-gateway` để xử lý đầu ra của các tools.
- Áp dụng thành công việc che mờ các thông tin PII (như email, số điện thoại, địa chỉ, họ tên) trước khi trả kết quả về cho LLM. Tinh chỉnh lại định dạng hiển thị gọn gàng (chỉ hiện 3 số đầu/cuối của SĐT và xoá chữ Masked).

**Task 5: Rate Limit (Giới hạn lượt gọi) theo User/Tool**
- **Triển khai In-memory Rate Limiter**: Tạo file `apps/mcp-gateway/src/policies/rate-limiter.ts`.
- **Cấu hình**: Giới hạn tối đa 20 requests / 1 tool / 1 user trong mỗi phút (Window 60s).
- **Tích hợp**: 
  - Áp dụng kiểm tra Rate Limit cho luồng REST API thông thường tại `POST /api/tools/call`.
  - Bỏ bypass `express.json` trong `app.ts` và can thiệp (intercept) luồng JSON-RPC của MCP Protocol qua SSE tại `POST /api/mcp/message` để map `sessionId` với `userId` và đếm lượt gọi tool chính xác.

### 2.5. Tinh chỉnh Data Masking (Che dữ liệu PII)
- **Vấn đề**: Số điện thoại bị che toàn bộ (`*******`), địa chỉ có dính chuỗi text `(Masked)` không đẹp mắt.
- **Giải pháp**: Cập nhật hàm `maskPhone` và `maskAddress` trong `apps/mcp-gateway/src/masking/masking-service.ts`:
  - Số điện thoại giờ sẽ giữ lại 3 số đầu và 3 số cuối (vd: `098***123`).
  - Địa chỉ chỉ hiển thị `***` gọn gàng.
